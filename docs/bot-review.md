# 自动撤回接入审查

审查来源：用户提供的 `tieba-extension/tieba-extension`，2026-10-17。
合入范围：嘉然吧频道的关键词自动撤回、独立 bot 登录、配置页面与处理记录。B站推送和聊天命令不在本次接入范围。

## 原实现的问题

- `bot.js handleMessage` 的违禁词分支提前返回；同一个词同时配置为违禁词和撤回词时，不执行撤回。
- `background.js dispatchToBot` 在判断是否有足够撤回信息之前就标记消息已处理。缺 `msg_key` 后失败，后续补齐也不能重试；普通消息轮询也没有接入检测。
- 去重集合仅在内存中保存，后台重启后失效，也未排除旧消息重放。
- `storage.js loadSettings` 缓存配置，后台未订阅配置变更；设置页也没有在外部变更后先清缓存。关键词、频道变化可能无法及时生效。
- `recallAsBot` 未主动查询机器人频道管理权限，且公用 HTTP 方法强制携带浏览器 Cookie，独立账号请求存在混用身份的可能。
- 接收账号的 authorId 被当作机器人自身判断，独立 bot 的消息没有正确排除。
- 恢复房间连接依赖 B站监控流程；未配置 B站 UID 时，后台重启可能不再监听已添加频道。
- 接口返回成功就记为“已撤回”，没有区分受理回执和实际频道撤回事件。

## 接入后的行为

复用原实现的字面关键词匹配和专用撤回接口，自动检测独立于聊天命令。频道从当前已验证的嘉然吧列表添加，绑定读取账号；执行时再次确认当前登录及配置版本。bot 登录、资料、权限和撤回请求均不携带网页登录 Cookie。

检测接入实时推送、侧栏轮询和后台 alarm 补读。只接受配置生效后的新消息，重放超过五分钟的消息不处理。消息标识缺失时等待补读；提交前持久化尝试记录，避免后台重启后重复撤回。停用、移除频道、换关键词/凭据或换网页登录账号会阻止尚未提交的旧任务，已经提交到服务端的请求不能取消。

本地最多保留 2000 条去重及处理记录，设置页展示最近 100 条。记录包含消息 ID、频道、匹配关键词和状态，不保存消息正文或机器人凭据。凭据仅存扩展本地受限存储，不写入代码、诊断导出和日志；设置页不回填已保存的凭据。

## 验证边界

自动化覆盖频道及账号隔离、权限变化、关键词变更、停用竞态、重启与重复推送、消息标识补全、凭据隔离以及设置页操作。所有请求使用模拟数据，没有在真实频道执行撤回。线上受理后仍需以频道撤回事件为准。

原有消息发送未送达的问题仍未解决，本次自动撤回接入不作为发送修复。
