# 机器人功能说明

贴吧频道聊天室扩展内置了一个聊天机器人，移植自 `py-bot/tieba_bot`，提供三类能力：

1. **聊天室内命令交互** —— 别人 `@机器人` 发送命令，机器人自动回复
2. **违禁词筛选** —— 命中关键词静默记录（不公屏刷屏）
3. **B站监控推送** —— 直播开播 / 新动态自动推送到订阅房间

---

## 一、快速上手（3 步）

### 第 1 步：启用机器人 + 配置

1. 右键插件图标 → **选项**，打开设置页
2. 勾选「**启用机器人**」总开关
3. 填「**机器人昵称**」——别人 @ 这个名字时机器人才会响应
4. 填「**机器人账号 BDUSS**」（可选）——粘贴独立机器人账号的 BDUSS，机器人就以该账号身份发言（与你的聊天账号分开）；留空则机器人用你当前登录账号回复
5. 填「**B站 UID**」（可选，用于 `/latest` 命令和直播/动态监控）
6. 点「保存」

> ⚠️ **昵称是命令响应的关键**。别人必须 `@这个昵称` 机器人才会响应；
> 昵称留空时，只做违禁词筛选，不响应任何命令。

### 独立机器人账号（可选）

机器人版支持**独立 bot 账号**：在设置页「机器人账号 BDUSS」粘贴另一个贴吧账号的 BDUSS 后，
机器人会以**该账号身份**发言，与你在浏览器里登录的聊天账号完全分开。

- **用途**：让机器人有独立形象，别人 @机器人昵称 时由 bot 账号回复，而非你的个人账号
- **获取 BDUSS**：登录目标 bot 账号后，在浏览器 DevTools → Application → Cookies → 复制 `BDUSS` 的值
- **留空**：机器人回退到用当前聊天账号发言（单账号模式）

### 第 2 步：把房间加入机器人

1. 打开侧边栏（点工具栏插件图标）
2. 输入吧名 → 选频道 → **进入频道**
3. 点房间标题旁的「**添加到机器人**」按钮

> 添加到机器人 = ① 记入启用房间列表 ② 加入该房间的 BLCP 实时通道。
> 之后即使不在这个房间的界面里，机器人也能收到它的实时消息并响应。

### 第 3 步：在聊天室测试

让任意其他账号（或你自己换设备）在频道里发：

```
@你的昵称 /help
```

机器人会回一条帮助信息，列出所有可用命令。

## 二、可用命令

| 命令 | 说明 | 是否需要 @ |
|------|------|-----------|
| `/help` | 显示帮助 | 是 |
| `/ping` | 测试机器人是否在线，回 `pong!` | 是 |
| `/latest` | 获取 B站最新动态 | 是 |
| `/sub live` | 订阅本房间的直播通知 | 是 |
| `/sub dynamic` | 订阅本房间的动态通知 | 是 |
| `/unsub live` | 取消订阅直播通知 | 是 |
| `/unsub dynamic` | 取消订阅动态通知 | 是 |
| `/status` | 查看本房间订阅状态 | 是 |
| `/banword 词` | 添加违禁词 | 是（管理员） |
| `/unbanword 词` | 移除违禁词 | 是（管理员） |
| `/listbadwords` | 列出全部违禁词 | 是（管理员） |

### 管理员命令说明

`/banword` `/unbanword` `/listbadwords` 需要发送者是**管理员**。管理员名单在设置页
「**管理员**」卡片中维护：选择房间 → 填入该用户的贴吧用户 ID（数字，即其主页网址里的那串数字）→ 添加。

> 管理员按房间分别管理：每个房间有自己的管理员名单。非管理员发管理命令会被**静默忽略**
> （不回复"无权"——因为扩展以你本人账号发言，回复会变成刷屏入口）。

## 三、工作原理

### 命令响应链路

```
BLCP 实时推送（新消息）
   → background.js onPush
   → dispatchToBot()（过滤：已启用房间 / 非本人消息 / 未处理过）
   → bot.js handleMessage()
        ├─ handleAdminCommand()   管理员命令（/banword 等）
        ├─ runCommand()           普通命令（需 @ 且昵称匹配）
        └─ processMessage()       违禁词静默记录
   → sendReply() → client.send() → BLCP method185 发回
```

### 关键判定逻辑

- **是否 @ 到自己**：三策略优先级——`atNames` 匹配 > `atUids` 匹配 > 文本 `@昵称` 匹配
  （贴吧昵称常带零宽/RTL 控制字符，比对前会做清洗）
- **是否自己发的**：用 `authorId`（baidu_uk）比对，跳过自己的消息防止自触发死循环
- **防重放**：`background.js` 维护 `botHandledIds`（最多 500 条 LRU），防止 BLCP 重连
  重放导致同一条命令被回复多次

### 违禁词

命中后**静默记录**（`botMarkLog`，最多 2000 条），**不公屏回复**——因为扩展以你本人
账号发言，公屏提示违禁词会暴露身份并造成刷屏。记录可在设置页「违规记录」查看/导出/清空。

### 撤回关键词（自动撤回）

命中「撤回关键词」（设置页单独列表，与违禁词分开）的消息，会被机器人**自动撤回**。

- **前提**：机器人账号（设置页「机器人账号 BDUSS」填的独立账号）必须在对应频道拥有
  **管理权限**（吧主/小吧主，即 `identity_role` 是管理员），否则贴吧会拒绝撤回。
- **结果**：撤回成功/失败都记入侧边栏「🤖 日志」，不公屏回复。
- **注意**：撤回依赖消息的 `msg_key`，BLCP 实时推送的消息若缺 `msg_key` 会撤回失败
  （记日志），此时该消息需等 REST 轮询补全后再命中才能撤。

## 四、B站监控

由浏览器 `chrome.alarms` 驱动，**每 5 分钟**检查一次（MV3 下 Service Worker 会被回收，
无法常驻轮询，只能用 alarm 定时唤醒）。

- 开播 → 推送到所有订阅了「直播」的房间
- 新动态 → 推送到所有订阅了「动态」的房间
- 推送文案以 `@全体成员` 开头（`AT_ALL_DATA` 是抓包得到的固定 at_data）

### ⚠️ 已知限制

1. **浏览器必须处于运行状态**。扩展完全关闭浏览器后，alarm 不再触发，监控停止。
   （这是 MV3 扩展的固有限制，无法像 Python 常驻进程那样 7×24 运行。）
2. **账号需保持登录**。SW 被回收后会自动从 BDUSS cookie 重连账号，但 cookie 失效后
   监控会静默失败（看 `[monitor]` 日志）。
3. **`@全体成员` 的 at_data 是抓包固定值**（`bot.js` 的 `AT_ALL_DATA`）。若换账号后
   `@全体成员` 失效，需重新抓包替换。

## 五、故障排查

### 机器人不回命令

按顺序排查：

1. **总开关开了吗？** 设置页「启用机器人」是否勾选。
2. **房间添加了吗？** 设置页「启用的房间」列表里有没有这个房间。
3. **昵称对了吗？** 设置页「机器人昵称」是否与贴吧显示名**完全一致**（含大小写/空格）。
4. **真的 @ 到了吗？** 消息里必须 `@昵称` 或通过贴吧的 @成员功能选中。
5. **本地代理在跑吗？** 机器人回复走 BLCP 发送，代理（`node proxy/proxy.js`）必须运行。
6. **看日志**：侧边栏「🤖 机器人日志」按钮，或浏览器扩展 Service Worker 的 console。

### 机器人重复回复

- BLCP 重连重放时会由 `botHandledIds` 去重；若仍重复，重启扩展清空缓存。

### B站监控不推送

1. B站 UID 填了吗（设置页）。
2. 房间订阅了吗（聊天室内 `@机器人 /sub live` 或 `/sub dynamic`）。
3. 浏览器是否开着、账号是否登录。
4. 看 Service Worker console 的 `[monitor]` 日志。

## 六、代码索引

| 文件 | 职责 |
|------|------|
| `bot.js` | 核心：`handleMessage`（命令/违禁词/@回应）、`monitor`（B站）、`AT_ALL_DATA` |
| `keyword.js` | `processMessage`（违禁词）、`handleAdminCommand`（管理员命令） |
| `bilibili.js` | B站直播/动态 API |
| `storage.js` | 配置、订阅、去重状态、违规记录、机器人日志、开关的持久化 |
| `background.js` | `dispatchToBot`（推送→机器人接线）、`runMonitor`（alarm 驱动） |
| `settings.html/js` | 设置页 UI |

> **接线要点**：`background.js` 的 `onPush` 必须把实时推送喂给 `handleMessage`，
> 否则机器人收不到命令。这是最容易遗漏的一环（历史版本曾因此导致机器人"添加后无反应"）。
